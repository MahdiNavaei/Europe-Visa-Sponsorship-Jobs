## Career Radar v1.2.1 — Matching & Freshness Fixes

v1.2.1 is a focused bug-fix and matching-quality release based on the first real-user feedback after the public launch.

### Fixed

- **Recommendation score scale** — the visa/sponsorship component was represented internally on a `0..1` scale but was previously multiplied by its ranking weight as if it were already `0..100`. This could suppress overall match scores by almost the full visa weight even for clearly eligible jobs. The component is now normalized to the same 100-point scale as the rest of the ranking inputs, with a regression proving an eligible visa-only component scores 100/100.
- **Recurring job freshness** — scheduled central ingestion no longer stops revisiting a company after its first successful fetch. Already-ingested healthy ATS boards become due again, are refreshed through a fair bounded scheduler, and new/changed/removed vacancies can reach existing desktop installations without reinstalling Career Radar.
- **Role coverage** — `Software Engineering` is now a first-class broad target role, with additional onboarding choices for Full Stack, Mobile, QA/Test Automation, and Security Engineering. Common `* Engineering` labels such as Data Engineering, Mobile Engineering, and Security Engineering are classified correctly.
- **Broad software-role matching** — a candidate selecting Software Engineering now strongly matches concrete backend, frontend, full-stack, mobile, QA, and security vacancies instead of being treated as unrelated simply because the vacancy uses a more specific family label.
- **Skill coverage** — the deterministic skill ontology has been substantially expanded across programming languages, backend, frontend, mobile, databases/data, AI/ML, cloud/DevOps, testing, observability, and security.
- **Onboarding skill UX** — the previous small flat skill list has been replaced with searchable, grouped skill sections. Groups most relevant to the selected target roles are shown first, while all supported skills remain available and existing profile skills are preserved.
- **ML broad-skill compatibility** — selecting a concrete ML framework/domain such as PyTorch, TensorFlow, NLP, Computer Vision, or MLOps now satisfies a broad Machine Learning requirement without assuming the reverse.
- **Role-classifier safety** — broad platform/engineering phrases still cannot turn explicit non-technical roles such as Service Designer or Product Manager into technical recommendations.

### Freshness behavior

The central scheduler runs hourly. Healthy verified sources become due after 18 hours and the current bounded scheduler is configured for an approximately 25-hour healthy-source revisit bound under successful workflow execution. Installed desktop clients check the published catalog every 24 hours while running; manual **Refresh jobs** remains available. Degraded or failing providers continue to follow explicit retry/backoff deadlines.

### What did not change

- Europe-only technical-market enforcement remains unchanged.
- Sponsorship eligibility remains deterministic and evidence-first.
- A sponsor-register entry alone still cannot make a job eligible.
- Hard work-authorization restrictions still override weaker positive evidence.
- Candidate profiles, Saved/Applied state, and notes remain local across catalog synchronization.
- No paid LLM/API dependency is required at runtime.

Thanks to the early users who installed the first public release and reported concrete matching issues. This release is directly shaped by that feedback.
